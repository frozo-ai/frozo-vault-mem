Local-first shared memory for your AI agents.

One Obsidian-friendly markdown vault. Multiple agents. Zero cloud dependency. Claude Code, Cursor, and any MCP-aware client read from and write to the same place — and a 30-min daemon quietly keeps it coherent.

Get started → Star on GitHub git clone github.com/frozo-ai/frozo-vault-mem

The problem

You work across multiple AI agents — each forgets what the others did.

Today your "memory" is conversation histories you can't search, project context copy-pasted into every new session, and Notion docs you forgot to update. vault-mem fixes this with one shared markdown vault all your agents read from and write to.

What you get

①

5 MCP tools, any agent

memory_write, memory_read, memory_search, memory_promote, memory_context. Works with Claude Code, Claude Desktop, Cursor, Windsurf, or any MCP-aware client.

②

Hybrid search, zero API keys

SQLite FTS5 BM25 + local ONNX MiniLM embeddings, fused via Reciprocal Rank Fusion. Runs entirely on your machine. No OpenAI bill.

③

A second brain you fully own

Every memory is a .md file at ~/vault-mem/. Open it in Obsidian. Commit it to git. If every AI vendor disappeared tomorrow, your knowledge survives.

④

Coherence without effort

A Python daemon runs every 30 min — promotes inbox writes, decays stale observations, links semantic neighbors, surfaces contradictions for review. You write; it tends the garden.

Install

macOS / Linux. Node ≥ 20, Python ≥ 3.12, pnpm, and uv.

1 — clone + build
git clone https://github.com/frozo-ai/frozo-vault-mem.git
cd frozo-vault-mem
pnpm install
pnpm --filter @vault-mem/mcp build
2 — materialize a vault
node packages/mcp/bin/vault-mem-mcp init     # creates ~/vault-mem/
node packages/mcp/bin/vault-mem-mcp doctor   # expect 9/9 PASS
3 — register with Claude Code
claude mcp add --scope user vault-mem \
  -e VAULT_MEM_PATH=$HOME/vault-mem \
  -- node $(pwd)/packages/mcp/bin/vault-mem-mcp
4 — schedule the keeper (optional, macOS launchd)
cp ops/keeper/com.vaultmem.keeper.plist ~/Library/LaunchAgents/
# edit REPLACE_USER + paths
launchctl load -w ~/Library/LaunchAgents/com.vaultmem.keeper.plist

Full setup including Cursor / Windsurf / generic MCP clients: see docs/INSTALL.md.

Architecture

Four small processes, each in the language that fits its job. Compose them independently — or just run the MCP server alone.

mcp server

TypeScript + official MCP SDK. Exposes memory_* tools over stdio. Localhost-only by default.

keeper

Python + uv. Every 30 min: triage, dedupe, link, decay, contradict, summarize. Haiku for cheap reasoning, Sonnet for judgment.

gatekeeper

Telegram approval gate for destructive ops (merge, supersede, archive recently-touched, resolve contradictions). Bring your own bot.

index

LanceDB + local all-MiniLM-L6-v2 for self-host. Re-indexes on file change. Rebuildable any time — .md is the source of truth.

Skills-file export

Turn your team's accumulated decisions into a skill bundle any agent can drop in.

vault-mem-mcp export-skill
node packages/mcp/bin/vault-mem-mcp export-skill my-project \
  --target claude --out ./out/

# Targets supported: claude | cursor | windsurf | generic

The exporter bundles the memories tagged for a project into the skill format consumed by your agent of choice. Drop the output directory in and your agent picks up your team's decisions at boot.

Privacy by default

  • ·No telemetry. Zero phone-home, opt-in only. The README spells out the opt-in flag on day 1.
  • ·No cloud dependency. Self-host runs entirely on your machine. Embeddings are local. No API keys required for core search.
  • ·DPDP/GDPR erasure cascade designed. Per-subject delete that cascades through markdown, embeddings, FTS, and audit log. Read the spec →
  • ·Audit trail. Every write/read/search recorded in JSONL with SHA-256-hashed query content (no raw queries persisted).
